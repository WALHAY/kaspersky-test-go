# Information Exchange Service

REST-сервис для обмена информацией об угрозах по [заданию](task.md).
Создаёт записи, возвращает их по MD5 и полностью заменяет изменяемые данные.
Контракт находится в [api/openapi.yaml](api/openapi.yaml), план — в [PLAN.md](PLAN.md).

Стек: Go 1.26, `net/http`, PostgreSQL 16, `pgx`, `goose`, `oapi-codegen`.
Модели и маршрутизатор сгенерированы из OpenAPI и включены в репозиторий.
Для обычной сборки кодогенератор устанавливать не нужно.

## Быстрый запуск с Docker

Нужны Docker Engine / Docker Desktop с запущенным daemon, Docker Compose v2
и `openssl`. Go на машине для этого способа не требуется.

```sh
cp .env.example .env
# Создать отдельные случайные значения и записать их в API_KEY и POSTGRES_PASSWORD в .env.
openssl rand -hex 32
openssl rand -hex 32
docker compose up --build -d
docker compose ps
curl http://localhost:8080/readyz
```

Оба значения обязательны. Для пароля в Compose используй hex-строку из примера:
пароль подставляется в URL подключения и не должен содержать неэкранированные
спецсимволы. `.env` исключён из Git и контекста Docker-сборки.

Compose дождётся готовности PostgreSQL, применит миграции отдельным контейнером
`migrate` и запустит API. Порт API опубликован на `127.0.0.1:8080`, порт БД
не публикуется. Контейнер API работает от непривилегированного пользователя
с файловой системой только для чтения. Данные сохраняются в именованном томе.

```sh
docker compose logs api migrate
docker compose down
```

`down` сохраняет данные. `docker compose down -v` удаляет том с записями.

## Примеры запросов

Подставь API-ключ из `.env` в переменную текущего терминала:

```sh
export API_KEY='ключ-из-файла-env'
```

Создание (`201 Created`, заголовок `Location: /info/{md5}`):

```sh
curl -i http://localhost:8080/info \
  -H "X-API-Key: $API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{"md5":"d41d8cd98f00b204e9800998ecf8427e","name":"Trojan.Win32.Generic","type":"trojan","severity":"high","description":"Крадёт учётные данные браузера","tags":["windows","credential-theft"]}'
```

Получение (`200 OK`):

```sh
curl -i http://localhost:8080/info/d41d8cd98f00b204e9800998ecf8427e \
  -H "X-API-Key: $API_KEY"
```

Полная замена (`200 OK`). В этом примере описание и метки очищаются:

```sh
curl -i -X PUT http://localhost:8080/info/d41d8cd98f00b204e9800998ecf8427e \
  -H "X-API-Key: $API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{"name":"Worm.Win32.Example","type":"worm","severity":"critical"}'
```

Пример ответа после создания:

```json
{
  "md5": "d41d8cd98f00b204e9800998ecf8427e",
  "name": "Trojan.Win32.Generic",
  "type": "trojan",
  "severity": "high",
  "description": "Крадёт учётные данные браузера",
  "tags": ["windows", "credential-theft"],
  "created_at": "2026-10-23T10:00:00Z",
  "updated_at": "2026-10-23T10:00:00Z"
}
```

## Модель и правила API

| Поле | Правила |
| --- | --- |
| `md5` | Обязательно при создании; ровно 32 hex-символа; хранится в нижнем регистре |
| `name` | Обязательно; 1–255 символов; пробелы по краям удаляются; пустое название запрещено |
| `type` | Обязательно; `trojan`, `virus`, `worm`, `ransomware`, `spyware`, `adware`, `rootkit`, `other` |
| `severity` | Обязательно; `low`, `medium`, `high`, `critical` |
| `description` | Необязательно; до 4096 символов; по умолчанию `""` |
| `tags` | Необязательно; до 20 уникальных меток длиной 1–64 символа; по умолчанию `[]` |
| `created_at` | Заполняет PostgreSQL; неизменяемое время создания в UTC |
| `updated_at` | Заполняет PostgreSQL; увеличивается после каждой замены, включая повторный PUT |

Длины измеряются в Unicode-символах до удаления пробелов. Регистр меток сохраняется,
их уникальность проверяется после удаления пробелов по краям. NUL запрещён в текстовых
полях. Тело должно быть одним JSON-объектом: неизвестные и повторяющиеся поля,
неверные типы и `null` отклоняются. `Content-Type` обязателен для POST/PUT;
допускается `application/json; charset=utf-8`.

`PUT` заменяет все изменяемые поля, сохраняет MD5 и `created_at`,
очищает пропущенные необязательные поля. Запись при отсутствии не создаётся.
Конкурентное создание одинакового MD5 возвращает один `201` и остальные `409`:
уникальность обеспечена первичным ключом, без проверки «прочитать, затем вставить».
Конкурентные PUT выполняются атомарно; итог содержит последнюю завершённую замену.

| Код | Причина |
| --- | --- |
| `400` | Некорректный MD5, JSON или поля |
| `401` | Нет действительного `X-API-Key` |
| `404` | Запись или маршрут отсутствует |
| `405` | Метод не поддерживается; ответ содержит `Allow` |
| `409` | MD5 уже существует |
| `413` | Превышен размер тела |
| `415` | Неподдерживаемый или отсутствующий Content-Type |
| `429` | Превышен лимит; ответ содержит `Retry-After` |
| `500` | Внутренняя ошибка; детали БД клиенту не раскрываются |

Ошибки возвращаются как JSON с обязательным `message` и необязательным `details`.
`GET /healthz` проверяет работающий HTTP-сервер; `GET /readyz` дополнительно проверяет
соединение с БД и возвращает `503` при её недоступности. Эти служебные маршруты
не требуют ключа и не входят в OpenAPI бизнес-методов.

## Конфигурация и локальный запуск

| Переменная | Значение по умолчанию |
| --- | --- |
| `DATABASE_URL` | Обязательный URL `postgres://…` |
| `API_KEY` | Обязательный ключ длиной не менее 32 байт |
| `HTTP_ADDR` | `:8080` |
| `RATE_LIMIT_PER_MINUTE` | `60`, допустимо 1–100000 |
| `MAX_BODY_BYTES` | `65536`, допустимо 1–1048576 |
| `REQUEST_TIMEOUT` | `5s`, допустимо 1ms–30s; ограничивает контекст обработки и SQL-запросов |
| `TLS_CERT_FILE`, `TLS_KEY_FILE` | Не заданы; для HTTPS задаются оба пути |

Для локальной разработки нужны Go 1.26+ и запущенный PostgreSQL 14+.
Сервис читает окружение; `.env` автоматически загружает только Docker Compose.

```sh
export DATABASE_URL='postgres://user:password@127.0.0.1:5432/threats?sslmode=disable'
export API_KEY='случайный-ключ-длиной-не-менее-32-байт'
make migrate
make run
# Или: make build, затем ./bin/server
```

Миграции встроены в бинарный файл и запускаются командой `server migrate`.
Повторное применение безопасно. Обычный запуск сервера не изменяет схему:
перед ним нужно выполнить миграции. В SQL есть секция Down для goose,
но команда сервиса намеренно выполняет только Up.

## Защита и HTTPS

Один API-ключ предоставляет доступ ко всем трём бизнес-методам. Сравнение ключей
выполняется за постоянное время. Ключи, заголовки и тела запросов не пишутся
в access log; служебные ошибки пишутся в структурированный журнал `slog`.
Для смены ключа измени окружение и перезапусти API.

Rate limit использует фиксированное минутное окно отдельно для каждого IP соединения,
включая запросы с неверным ключом. `X-Forwarded-For` не учитывается. Счётчики находятся
в памяти одного процесса и сбрасываются при перезапуске; за границей двух окон
возможен всплеск до удвоенного лимита. Число IP ограничено 10000, при заполнении
новые IP получают `429` до следующего окна. За reverse proxy все клиенты могут
разделять его IP; для нескольких реплик нужен общий лимитер или лимит на прокси.

Сервер поддерживает TLS 1.2+, ограничивает размер заголовков и тела, задаёт таймауты
чтения и записи и корректно завершает активные запросы по SIGINT/SIGTERM.
Для внешнего доступа включи HTTPS, чтобы API-ключ передавался по шифрованному каналу.
Пример локального сертификата (нужен OpenSSL с `-addext`):

```sh
mkdir -p certs
openssl req -x509 -newkey rsa:2048 -nodes -days 30 \
  -keyout certs/server.key -out certs/server.crt \
  -subj '/CN=localhost' -addext 'subjectAltName=DNS:localhost,IP:127.0.0.1'
export TLS_CERT_FILE="$PWD/certs/server.crt"
export TLS_KEY_FILE="$PWD/certs/server.key"
make run
curl --cacert certs/server.crt https://localhost:8080/healthz
```

Сертификаты и приватные ключи исключены из Git и Docker-сборки. Для публичного
сервиса используй сертификат доверенного центра и подключение к PostgreSQL
с проверкой сертификата (`sslmode=verify-full`). MD5 здесь — идентификатор файла,
а не криптографическое средство защиты.

## Проверки

```sh
make test             # Unit-тесты и HTTP-тесты с race detector, БД не нужна
make integration      # Требует TEST_DATABASE_URL
make test-docker      # Все тесты с отдельной PostgreSQL в Docker, локальный Go не нужен
make check            # Генерация, unit-тесты, vet, golangci-lint и сборка
make coverage         # Покрытие написанного вручную кода internal
```

Пример интеграционных тестов с существующей тестовой БД:

```sh
export TEST_DATABASE_URL='postgres://user:password@127.0.0.1:5432/threats_test?sslmode=disable'
make integration
```

Интеграционные тесты создают случайную схему и удаляют её после завершения.
Учётной записи нужна возможность CREATE SCHEMA; существующие таблицы не очищаются.
Проверяются HTTP → PostgreSQL, миграции, нормализация MD5, замена и сохранение полей,
конкурентное создание, ограничения БД и отмена контекста. Если указан тег `integration`,
отсутствующий TEST_DATABASE_URL вызывает ошибку, а не пропуск тестов.

GitHub Actions запускает интеграционные тесты с PostgreSQL 16, статический анализ,
проверку генерации и сборку Docker-образа.

После изменения OpenAPI выполни `make generate`. Версии кодогенератора и линтера
закреплены; `make check-generated` проверяет, что сгенерированный файл актуален,
даже если проект ещё не инициализирован как Git-репозиторий.

## Структура

```text
api/                 OpenAPI, конфигурация генерации и сгенерированный контракт
cmd/server/          конфигурация запуска, HTTP/TLS и graceful shutdown
internal/config/     проверка переменных окружения
internal/threat/     модель и валидация, независимые от HTTP и БД
internal/httpapi/    обработчики, проверка OpenAPI, middleware и HTTP-тесты
internal/postgres/   SQL-хранилище, запуск goose и интеграционные тесты
migrations/          SQL-миграции, встроенные через embed
```

Интерфейс хранилища объявлен на стороне HTTP-потребителя; PostgreSQL реализует его
без зависимости от HTTP. Тестовое хранилище в памяти используется только в unit-тестах.
ORM и отдельный слой сервиса не добавлены: бизнес-правила ограничиваются нормализацией
и валидацией, а операции хранилища — тремя атомарными запросами.
